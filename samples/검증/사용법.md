# 자료 검증 재현

저장소 최상위에서 실행한다. 응용 프로그램 파일이나 의존성 설정을 변경하지 않는다.

필요 환경: 타입 제거 기능이 있는 노드 24 이상, 파이썬과 `pypdf`, `Pillow`.

```sh
node samples/검증/탐지검증.cjs
python samples/검증/문서검증.py
```

첫 번째 명령은 현재 `src/rules/rules.ts`를 읽고 핵심 네 규칙의 수동 정답, 31개 경계 사례, 일곱 규칙 통합 시연, 저장된 여섯 규칙 관측값을 비교한다. 현재 구현은 계좌번호를 포함한 일곱 규칙이며, 기존 샘플 관측값 파일 이름은 유지한다. 두 번째 명령은 실제 문서의 글자 추출 결과와 본문 파일 일치, 이미지 객체 수, 문서 내부 이미지 크기, 정답 영역의 범위를 검사한다.

현재 기준 결과:

- 글자판 20개, 21쪽, 핵심 네 규칙 정답 50건 일치.
- 기존 여섯 규칙 관측값 54건을 유지한다. 추가 네 건은 알려진 이름 접두어 오탐이다. 계좌번호를 포함한 일곱 규칙 관측값은 56건이며 두 계좌번호가 추가된다. 기존 여섯 규칙 비교에서는 계좌번호만 제외하고, 계좌번호는 독립 경계 사례와 단위 검사로 확인한다.
- 경계 사례 31개와 일곱 규칙 통합 시연 7건 일치. 추가 사례는 이메일 전체 구간, 이름 라벨·미입력 상태값과 계좌번호를 검사한다.
- 이미지 문서 8개, 수동 정답 영역 118개 구조 검사 통과.

규칙이 의도적으로 바뀌면 수동 정답과 변경 이유를 먼저 검토한다. 이후에만 `node samples/검증/탐지검증.cjs --기준저장`으로 코드 관측값을 갱신한다. 이 옵션은 수동 정답을 변경하지 않는다.

이미지 글자 인식률, 화면 하이라이트, 선택 마스킹, 다운로드한 문서의 원문 제거는 이 검사로 증명되지 않는다. 해당 기능에서 별도로 검증한다. 문서 배치는 제작 단계에서 렌더링해 확인했다.
