검사일: 2026년 10월 31일 한국 시각 오전 7시 전후. 실제 주소: https://garim-26.vercel.app/ . 배포 식별자는 미확인이다. 코드 확인 기준은 최신 기본 브랜치 `74305c0`이며 배포 코드와 동일하다는 보장은 없다. 검증 전용 브랜치는 `codex/42-integration-verification`이다.

**판정: 전체 완료 조건 미충족.** 개인 모드의 일부 실제 흐름은 통과했으나 기업 강제 가림에서 실패했고 관리자 통계는 준비 중이다. 검증 절차나 도구 자체의 성공을 제품 전체의 통과로 세지 않았다.

## 실제 배포에서 확인한 결과

## 검증 도구 확인

- `node --test tests/browser/integration-evidence.test.mjs`: 4개 검사 통과. 정상 기록, 개인 0행, 중복·잘못된 입력·0건·원문 열·기존 기록 변경·합계 불일치 거부, 동점·0건 프로필을 검사한다.
- `node tests/browser/integration-evidence.mjs tests/browser/integration-example.json`: 예시 자료 통과. 실제 배포 기록 검증 결과가 아니다.
- `node tests/browser/downloaded-pdf-check.mjs '실제 다운로드 경로'`: 위 실제 파일 통과. 가짜 원본 PDF는 실패하여 원본을 가림 결과로 잘못 통과시키지 않음을 확인했다.
- 제품 코드·의존성·환경 파일은 수정하지 않았다. 파이썬의 문서 검사 의존성이 없어 기존 문서 검사를 다시 실행하지 않았으며 #42 범위상 기존 모듈 검사 재작성도 하지 않았다.

## 선행 작업과 후속 확인

#36의 관리자 선택 해제 결함과 #38의 준비 중 화면을 해당 이슈 댓글로 알리려 했으나 깃허브 연결이 쓰기 권한 부족(403)으로 거부했다. **댓글 전달은 완료되지 않았다.** 이 문서에 재현 조건을 남겼으며 제품 코드는 담당 범위 확인 전 수정하지 않았다.

#36·#37·#38·#39·#40 및 #10 배포 반영 후 [전체 절차](../tests/browser/integration-procedure.md)의 시나리오별로 실제 실행하고 결과표를 갱신해야 한다. #41에는 위 두 화면 크기의 부분 결과를 연결하고 실제 기기·터치·키보드를 별도 확인한다. 원본 네트워크 기록, 계정·인증 정보, 실제 사용자 번호, 원문 조회 자료는 결과물과 깃에 넣지 않는다.

## 검토 요청 상태

검증 브랜치는 원격 저장소에 올라갔다. 깃허브 연결의 검토 요청 생성도 쓰기 권한 부족(403)으로 실패했다. 저장된 깃 인증을 별도 요청에 재사용하려던 대체 작업은 자동 승인 검토가 인증 비밀값 탐색 위험으로 실행 전에 거부했으며 인증 값은 읽거나 저장하지 않았다. 따라서 검토 요청과 담당 이슈 댓글은 아직 생성되지 않았다. [브랜치 검토 요청 만들기](https://github.com/sbychul/2026_hackathon/compare/main...codex/42-integration-verification?expand=1)에서 초안으로 등록하고 #42는 열어 둔다. 제품 결함은 #36, 통계 미제공은 #38 담당 범위에서 반영 후 재검증해야 한다.
