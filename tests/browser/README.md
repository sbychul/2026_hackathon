# PDF 저장 연결 검증

1. 저장소에서 `npm run dev`를 실행한다.
2. 크롬에서 개발 서버의 `/tests/browser/pdf-export.html`을 연다.
3. 샘플 문서를 내려받아 원본 입력에서 선택한다. 기존 탐지 함수가 총 5건을 찾아야 한다.
4. 잘못된 좌표 차단 검사를 누르고 오류가 표시되는지 확인한다.
5. 가린 문서 내려받기를 누른다. 실제 파일명이 `가림-검증결과.pdf`인지 확인한다.
6. 내려받은 파일을 결과 입력에서 선택한다. 모든 검증이 통과해야 한다.
7. 원본과 결과 미리보기를 비교한다. 개인정보만 검게 가려지고 제목·일반 문장은 읽을 수 있어야 한다.

검증은 실제 PDF 렌더링, 기존 탐지 함수, 제품 저장·다운로드 함수, 실제 다운로드 파일의 재업로드를 사용한다. 두 페이지 모두 텍스트층이 없고 다섯 가림 영역 내부가 모두 검은 픽셀인지 검사하며, 회전 페이지 크기와 원본 제목 제거도 확인한다.

4번 좌표 추출은 미구현이므로 제공된 샘플의 고정 좌표를 사용한다. 임의 PDF의 자동 좌표 추출을 보장하는 검증이 아니다. 좌표 약속은 기본 회전이 적용된 배율 1 화면의 왼쪽 위 기준이며 페이지 번호는 1부터 시작한다. 4번 구현과 연결할 때 해당 좌표 약속과 실제 문서 사례를 추가 확인해야 한다.

이 페이지는 개발 서버에서만 사용하는 검증 도구이며 실제 앱 화면을 변경하지 않는다. 실제 개인정보 문서를 사용하지 않는다.

## 사용자 첨부 등록서 검증

`attached-pdf.html`은 파일 선택창 대신 로컬 서버를 통해 첨부 문서를 읽는 별도 검사 화면이다. 원본 사본은 `node_modules/.tmp/attached-source.pdf`에 두고 개발 서버에서 `/tests/browser/attached-pdf.html`을 연다. 첨부 등록서를 연 뒤 다운로드 버튼을 누른다. 실제 다운로드 폴더에 저장된 `04_거래처_담당자_등록서_가림검증.pdf`를 `node_modules/.tmp/attached-downloaded.pdf`에 복사한 다음 실제 다운로드 파일 검사를 누른다. 이 임시 PDF들은 깃에서 제외된다.

2026년 10월 31일 크롬 검증 결과: 등록서 1쪽에서 전화번호·이메일 2건 탐지, 실제 다운로드 27,985바이트. 다운로드 파일과 재검사 사본의 해시가 일치했다. 결과는 1쪽, 추출 텍스트 0개, 주석 0개였고 원본 페이지 크기가 유지되며 두 가림 영역 내부는 모두 검정이었다. 원본과 결과를 시각적으로 비교해 제목·일반 문장·표가 유지되는 것을 확인했다.

이 검증의 좌표 연결은 가로 글자 조각 전체를 가리는 임시 방식이며 4번 기능의 완성본이 아니다. 탐지 규칙은 현재 로컬 기본 코드이며 검토 요청 14번은 병합하지 않았다. 대표번호·사업자번호와 이 샘플의 담당자 표기는 현재 탐지 범위에 포함되지 않는다.
