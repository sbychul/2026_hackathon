# PDF 직접 가리기 검증

## 실행

39번 작업 공간에서 의존성을 설치한 뒤 개발 서버를 실행하고 `/tests/browser/pdf-manual.html`을 연다. 서버를 종료하면 접속할 수 없다. 모델이나 실제 개인정보는 필요하지 않다.

## 확인 순서

1. 개인 모드에서 `영역 추가`를 누르고 첫 페이지 위를 드래그한다. 목록에 직접 영역이 추가되고, 만드는 동안 내려받기가 비활성화되는지 확인한다.
2. 목록에서 해당 영역을 취소한다. 자동 탐지 선택과 건수가 바뀌지 않는지 확인한다.
3. 좌표로 첫 페이지에 왼쪽 80, 위쪽 200, 너비 100, 높이 50을 추가한다. 두 번째 페이지에는 왼쪽 100, 위쪽 60, 너비 50, 높이 60을 추가한다. 다른 좌표를 직접 지정해도 된다.
4. 두 번째 페이지로 이동해 회전을 누르고 125%로 확대한 뒤 글자 일부를 드래그한다. 추가 회전과 원본 회전은 저장 좌표와 독립적이며, 선택한 위치가 검게 저장되어야 한다.
5. 최종 미리보기 준비 완료를 기다려 `가린 PDF 내려받기`를 누른다. 바로 위의 `실제 내려받은 파일 검사`에서 방금 내려받은 파일을 선택한다.
6. 두 페이지에 원문 텍스트가 없고, 내려받기 순간의 직접 영역 내부가 검으며, 실제 글꼴·주석·양식·첨부가 없다는 통과 안내를 확인한다. 빈 글꼴 목록은 글꼴이 남은 것으로 판정하지 않는다.
7. 기업 모드로 바꾼다. 자동 탐지의 항목별·종류별 선택이 비활성화되며 직접 추가와 개별 취소는 가능한지 확인한다.
8. 직접 영역 없이 내려받거나 새로고침 후 이전 파일을 검사하면 검사 대기 안내가 나와야 한다. 이 경우 직접 영역을 다시 추가하고 새 파일을 내려받아 검사한다.
9. 드래그 도중 취소 키, 페이지 밖 포인터, 역방향 드래그, 여러 페이지의 복수 영역, 빠른 추가·취소를 확인한다. 이전 버전 파일을 최종 결과로 내려받을 수 없어야 한다.

## 검사 명령

- `npm test`: 좌표 변환 18개를 포함한 전체 검사.
- `npm run build`, `npm run lint`: 제품 코드 빌드와 정적 검사.
- 검증 화면은 제품 빌드 대상 밖이므로 별도로 형식을 검사한다.

```powershell
node node_modules/typescript/bin/tsc --ignoreConfig --noEmit --target es2023 --lib es2023,DOM,DOM.Iterable --module esnext --moduleResolution bundler --jsx react-jsx --types vite/client --skipLibCheck tests/browser/pdf-manual.tsx
```

## 실제 확인 결과

2026년 10월 31일 브라우저에서 드래그 추가·개별 취소·다운로드 잠금을 확인했다. 기업 모드에서 자동 선택 해제를 막는 것도 확인했다. 개인 모드의 두 페이지에 세 영역을 추가하고, 세 번째 영역은 125% 확대 및 90도 추가 회전 상태에서 드래그했다. 실제 내려받은 파일을 다시 선택했을 때 세 영역의 검은 픽셀, 두 페이지의 텍스트 0개, 실제 글꼴·주석·양식·첨부 없음 검사를 통과했다.

## 다른 이슈와 연결

- 기업 결과 화면 담당은 `PdfResultPage`에 `mode="company"`를 전달한다. 기본값은 개인 모드다. 인증 및 화면 전환 파일은 이 이슈에서 수정하지 않는다.
- 직접 영역은 자동 탐지 목록과 별도 상태에 있으며 내보내기 직전에만 합친다. 통계 담당은 자동 탐지 결과만 집계하고 직접 영역을 룰별 통계에 더하지 않는다.
- 추출·이미지화 저장 모듈은 변경하지 않았다.
- 모바일 터치와 키보드 조작의 종합 검증은 해당 접근성 이슈와 함께 마무리한다.
