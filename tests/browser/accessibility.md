# 모바일·키보드 접근성 검증 (#41)

`main`에 병합된 화면(로그인, 입력, 텍스트 결과, PDF 결과)만 대상으로 한다. 관리자 대시보드(#38), PDF 직접 가리기(#39), 기업 강제 마스킹(#36), 글자 인식 화면 연결(#40)은 각 작업이 병합된 뒤 같은 절차로 이어서 검증한다.

## 절차

1. 저장소에서 `npm run dev`를 실행하고 크롬에서 개발 서버를 연다.
2. 모바일(375×812, 터치 장치 흉내)과 데스크톱(1440×900) 크기에서 각각 아래를 확인한다.
3. 마우스를 쓰지 않고 Tab·Shift+Tab·Enter·Space만으로 진행한다.
   - 로그인 화면에서 "개인으로 사용하기"로 들어간다. 초점이 "개인정보 가리기" 제목으로 옮겨져야 한다.
   - 입력 칸에 `samples/한국어/텍스트`의 가상 본문을 넣고 "개인정보 찾기"를 누른다. 초점이 결과 제목으로 옮겨져야 한다.
   - 묶음 번호 버튼에서 Space로 종류 전체를 끄고 켠다. 개수 표시가 `0/1`처럼 바뀌어 색 없이도 상태를 알 수 있어야 한다.
   - "가릴 글자 입력" 칸에 놓친 값을 입력하고 Enter를 누른다. 원문에 나오는 곳이 모두 "직접 가린 부분"에 들어가야 한다.
   - "취소"를 누르면 그 항목이 빠지고 초점이 입력 칸으로 돌아와야 한다.
   - "가린 결과 복사"를 누른다. 버튼 글자와 화면 읽기용 상태 안내가 함께 바뀌어야 한다.
   - "처음부터 다시"를 누르면 초점이 입력 화면 제목으로 돌아와야 한다.
4. 모바일 크기에서 원문 글자를 길게 눌러 선택한 뒤 "선택한 부분 가리기"를 누른다. 버튼을 누르는 순간 선택이 풀려도 마지막 선택이 가려져야 한다.
5. 긴 파일명의 글자판 PDF(`samples/한국어/가짜 샘플(이미지X)`)를 첨부한다. 첨부 칸의 파일명은 두 줄까지 보이고, 미리보기 머리의 파일명은 칸 안에서 말줄임 처리돼야 한다. 미리보기가 끝나면 내려받기 버튼이 켜져야 한다.
6. 두 크기 모두 가로 스크롤이 생기지 않아야 한다.

## 2026년 10월 31일 크롬 검증 결과

- 375×812: 가로 스크롤 없음(문서 너비 375px). 위 3~5번 모두 통과. 이름 라벨이 없는 두 번째 이름을 "가릴 글자 입력"으로 가렸다. 선택 후 원문 밖으로 선택이 풀려도 "선택한 부분 가리기"가 켜진 상태를 유지했다.
- 1440×900: 가로 스크롤 없음. 터치 화면용 크기 조정이 적용되지 않아 기존 시안 크기를 유지했다.
- 명도 대비: `--text-tertiary`를 `#8a8a84`(흰 배경 3.5:1)에서 `#6b6b65`(흰 배경 5.3:1, 페이지 배경 4.8:1)로 바꿨다. 초록 강조색과 흰 글자는 5.4:1이다.

## 남은 제약

- 실제 휴대폰이 아니라 크롬의 모바일 화면 흉내로 확인했다. iOS 사파리의 길게 눌러 선택하기는 실기기에서 다시 확인해야 한다.
- 화면 읽기 프로그램(NVDA, VoiceOver)으로 직접 들어 보지는 않았다. 상태 안내는 `role="status"` 영역의 글자가 바뀌는 것까지만 확인했다.
- PDF 이외 파일을 첨부하면 브라우저 기본 경고창이 뜬다. 키보드로 닫을 수 있지만 화면 안 안내로 바꾸는 것은 이번 범위에 넣지 않았다.
- 원문 칸은 키보드 커서로 글자를 고를 수 없다. 키보드 사용자는 "가릴 글자 입력"을 쓴다.
