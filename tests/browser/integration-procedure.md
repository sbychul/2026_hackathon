# 실제 배포 통합 검증 (#42)

제품 화면에서 실행한다. 별도 PDF 시험 화면이나 모듈 검사 성공으로 대체하지 않는다. 원문은 저장소의 가짜 자료만 사용한다. 기업 검사는 허가된 검증 계정만 사용하며 기록은 누적된다. 검사 뒤 임의 삭제하지 않는다.

## 실행 준비

1. #10의 실제 주소, 배포 식별자, 한국 시각, 브라우저 버전, 운영체제, 화면 크기, 모델 캐시 상태를 기록한다. 배포 식별자를 확인할 수 없으면 미확인으로 남긴다.
2. 관리자와 직원 계정에 사용자가 직접 로그인한다. 비밀번호·토큰·전체 인증 요청은 출력하거나 저장하지 않는다. 기록 조회는 관리자 권한의 전체 페이지를 끝까지 읽어야 하며 화면에 보이는 일부 행만 사용하지 않는다.
3. 다른 사용자 작업이 없는 검사 시간대를 잡는다. 전후 조회 사이 다른 작업이 발생하면 기대값을 임의 수정하지 말고 해당 시나리오를 다시 준비한다.
4. 아래 시나리오마다 전후 기록과 관리자 재조회 수치를 대조한다. 실제 사용자·기록 번호는 자료를 로컬에서 정리할 때 `검증1`처럼 일관된 별칭으로 바꾼다. 이름·이메일·원문·파일명·생성 시각·인증 값은 대조 파일에 넣지 않는다.

## 입력과 수동 정답

- 텍스트는 `samples/한국어/텍스트/00_전체규칙_통합시연.txt`에 가짜 `계좌번호: 1234567890`과 일반 문구 `직접가림시험`을 덧붙인다. 일곱 룰 각각 1건이다. 직접 문구는 자동 탐지 0건이다.
- 글자 PDF는 `samples/한국어/가짜 샘플(이미지X)/04_거래처_담당자_등록서.pdf`를 사용한다. 전화번호·이메일 각 1건이다.
- 0건 입력은 `20_일반_회의실_사용_안내문.txt`를 사용하고 실행 전 수동 정답도 확인한다.
- 글자 인식은 `가짜 샘플(이미지O)`의 선명·흐린 스캔과 `정답/이미지판_가림대상과좌표.json`을 대조한다. 인식 오류를 기대값으로 덮어쓰지 않는다. 글자 PDF·스캔 PDF·혼합 문서·지원 이미지 각각 기록한다. 최종 지원 입력과 이미지 출력 형식은 #40 확정 후 따른다.

## 전후 기록·관리자 수치 대조 도구

저장소 최상위에서 노드로 실행한다. 추가 의존성은 없다.

```powershell
node tests/browser/integration-evidence.mjs tests/browser/통합증거.local
node --test tests/browser/integration-evidence.test.mjs
```

자료 구조 예시는 `integration-example.json`에 있다. **예시는 도구 사용법이며 실제 배포 증거가 아니다.** `before`와 `after`는 전후 전체 기록, `expected`는 이 시나리오에서 추가될 수동 정답 기록이다. 개인·직접 가리기만·0건 시나리오는 `expected: []`로 둔다. 실제 추가 행의 별칭을 기대 행에도 대응시킨다. `dashboard`는 화면에서 독립적으로 옮겨 적은 값이며 집계 함수로 생성하면 검증 의미가 사라진다. 가림 이전 전체 누적값을 사용한다. 프로필 별칭은 실제 사용자 번호 정렬을 보존하도록 배정한다.

도구는 기존 행 변경·누락, 추가 행 중복·누락, 잘못된 입력 방식·룰·0건 저장, 수치 불일치를 실패 처리한다. 원문 등 알 수 없는 열을 거부하고 오류에 입력을 출력하지 않는다. 다만 사람이 정리한 자료의 진위를 검증하거나 비전송을 증명하지 않는다. 실제 저장 열 허용 목록은 다음 절차로 별도 검사한다.

## 원문 비전송·저장 열 검사

1. 브라우저 개발 도구의 네트워크 기록 유지를 켜고 입력 전부터 로그인·마스킹·내려받기·관리자 재조회까지 관찰한다. 요청 본문·경로·질의·웹소켓·비콘·작업자 요청을 확인한다. 원본 네트워크 기록 파일은 인증 정보가 포함되므로 결과물이나 깃에 저장하지 않는다.
2. 인증 요청의 계정·비밀번호와 인증 헤더는 문서 원문 전송과 구분하되 결과에 옮기지 않는다. 데이터 저장 요청은 `user_id`, `rule_id`, `count`, `input_type`만 허용한다. 식별자·시각은 데이터베이스 생성값이다. 실제 테이블 열 목록에도 원문·파일·인식 글자·탐지 값 열이 없는지 확인한다.
3. 모델·실행기·사전의 공개 정적 파일 수신은 목적지 출처·자산 종류·수신 크기·성공 여부만 기록한다. 공개 자산 수신이 문서 전송이라는 뜻은 아니다. 요청 본문이나 질의에 파일명·원문·인식 글자·개인정보 값이 섞이지 않아야 한다. 입력한 가짜 표식이 요청에 보이면 실패다.
4. 콘솔·오류 수집에도 원문이 없는지 확인한다. 기록은 목적·성공 여부·열 이름만 남긴다. 개발 도구에서 관찰할 수 없는 영역은 미검증으로 적는다.

## 실제 내려받은 PDF 검사

```powershell
node tests/browser/downloaded-pdf-check.mjs '실제 내려받은 가짜 자료의 절대 경로'
```

저장소 의존성이 설치된 환경에서 실행한다. 모든 쪽의 텍스트층·주석·첨부·문서 동작 부재, 페이지 이미지 존재와 파일 검증값을 확인한다. 원본 파일을 주면 실패해야 한다. 이 검사는 검정 영역의 위치를 증명하지 않는다. 실제 내려받은 파일을 다시 열고 원본과 같은 크기로 렌더링하여 수동 정답 영역과 직접 지정 영역이 검게 가려졌는지, 선택 해제한 부분과 제목·일반 문구가 유지되는지 별도로 확인한다. 화면 미리보기만으로 내려받은 파일을 확인했다고 쓰지 않는다.

## 결과 작성

`docs/integration-verification-42.md`에 실제 실행한 범위만 기록한다. 각 시나리오는 통과·실패·미실행·선행 작업 대기로 나눈다. 실패는 담당 이슈에 재현 조건과 기대/실제를 알리고 담당 범위 확인 후에만 제품 코드를 수정한다. 비밀번호·비밀 키·토큰·실제 개인정보는 어떠한 증거에도 포함하지 않는다. 실제 조회 자료와 내려받은 파일은 깃에서 제외되는 `*.local` 또는 기존 제외 임시 폴더에만 보관한다.
